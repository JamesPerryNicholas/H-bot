# H bot 本地维护

源码：`D:\deepseek bot\DS-Bot-dev`。当前安装：`D:\heng bot`。两者独立，源码修改不会自动进入当前运行的应用。

用户已要求持续改进 H bot 的本地代码和配置。每轮只处理一个有证据、能验证的改进；检查没有发现可处理的问题时，记录结果即可。

## 维护入口

在源码根目录运行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\maintain.ps1 snapshot
powershell -NoProfile -ExecutionPolicy Bypass -File .\maintain.ps1 check
```

入口优先使用项目已有的 `.tools/node/node.exe`，检查最低 Node 版本，不安装或升级依赖。

`snapshot` 在改动前保存源码与配置快照。`check` 先保存当前源码快照，再依次执行维护脚本测试、桌面端单元测试、插件构建一致性、插件 lint 和插件单元测试。任一步失败即返回非零退出码，报告明确列出尚未执行的检查。检查结束时还会核对源码散列；检查期间发生新增、删除或修改也会使结果失败。完整输出保留在各检查的本地日志中。

配置为根目录的 `maintenance.config.json`。快照、SHA-256 清单、报告和日志位于 `.h-bot-maintenance/<时间-标识>/`；最近一次检查结果另存为 `.h-bot-maintenance/last-report.json`。快照仅覆盖应用、插件和维护相关源码，排除依赖、构建产物、本地数据、环境文件和凭据。它不是聊天、浏览器登录或整套安装的备份。快照不覆盖已有文件；源码中的符号链接会使快照中止。

同一时间只允许一个维护命令。异常中断后可能留下 `running.lock`：先核对其中 PID 是否仍在运行，确认已结束后才移除该锁文件，不能为了继续而杀死其他任务。

## 每轮完成标准

1. 阅读根目录及修改范围内的代理约定；保留用户已有改动。当前目录是源码导出，没有 Git 历史，不能假定已有分支或可回滚提交。
2. 明确一个问题、原因和验收标准，先运行 `snapshot`。常规、可回滚的本地改进自主执行。
3. 做最小完整修改；优先解决可靠性、可诊断性和有测量依据的性能问题。没有证据时不为了升级而改代码。
4. 执行相关局部验证和 `check`。公共接口、权限、数据写入或核心流程还必须补充对应集成/烟雾验证，不能仅凭该脚本宣告完成。
5. 修改界面时从源码构建，并在实际应用中检查。只修改源码或只通过单元测试不代表运行中的应用已升级。
6. 留下简短记录：改动、证据、验证结果、剩余风险及是否已经部署。未部署的改动需明确标注。

维护脚本不提交、不推送、不下载更新、不修改聊天或凭据、不替换安装目录，也不重启应用。发布运行中的版本应单独准备构建、运行版本备份、打包验证和恢复方式；涉及中断正在进行的对话时先协调时机。现有本地版关闭上游自动更新的配置应保留。

定时维护需要单独配置调度器。本文件和维护脚本本身不会让代理在没有新消息时持续运行。
